# 정찰제와 사진 AI 견적 및 예약

**2026-10-11 최신 구현·검증:** 사진 AI 분석 → 작업·예상 가격 → EMS 동일 저장본 → 현장 확인 후 필요한 가격 조정 흐름을 연결했다. 시작가는 **A$1,500 GST 별도 / A$1,650 GST 포함**이며, AI가 관찰한 문·서랍 수량과 손상에 [L&K 초기 가격 v1](39-sydney-cabinet-pricing-v1.md)의 서버 계산 규칙을 적용한다. 공개 Sydney 가격은 참고 자료이며 공식 시장 평균이 아니다. 회사 Chrome에서 지정 손상 사진 두 장 업로드·분석 중/완료 후 새로고침·고객/EMS 동일 결과와 320px 메뉴·키보드를 확인했고 콘솔 메시지는 0건이었다. 실제 결과는 추가 범위·심한/분류되지 않은 손상 확인이 필요해 `review_required`, 총액 null로 저장됐다. 전체 검사 **488/488**와 lint·타입·빌드가 통과했고 신규 가격 SQL을 회사 Supabase에 적용했다. 충분한 전체 사진으로 숫자 예상 총액을 내는 실제 인수, 현장 조정, 고객 이메일 본인 확인·서명·예약, Vercel 환경·상시 worker 운영은 남아 있다. 과거 `unconfigured`/`awaiting_company_rates` 결과는 유지한다. [실제·합성 검증과 남은 범위](../verification/2026-10-11-pricing-browser-qa.md)를 따른다. 커밋·main 병합·푸시는 승인됐으나 이 문서 갱신 시점에는 미실행이며 배포도 미실행이다.

**2026-10-02 KCP 개정:** [32번 고객 제출 계약](32-client-quote-signature-submission.md)과 [25번 P0~P8](25-kcp-quote-to-booking-implementation.md)을 우선한다. 고객 정보 선저장 → 서비스/사진 → AI/승인 가격 → 고객 approve → 앱 달력 → 최종 확인/서명/제출 → 견적·서명 계약 이메일 → 회사 Calendar 순서다. 회사 기간·충돌 확인 전에는 요청이며 예약된 날짜 선택은 차단한다. 당시 초기 견적은 담당자 승인으로 계획했으나, 10월 11일 개정으로 KCP 예상 견적은 평가·회사 가격 기준을 충족하면 고객에게 자동 표시한다. 실제 AI·Resend·가격·기간 규칙은 후속 선행 조건이며 임의로 활성화하지 않는다.

## 기본 원칙

고객이 확정할 수 있는 것은 범위·금액·조건이 고정된 견적이다. 사진만으로 숨은 손상, 기초 재질, 정확한 면적이나 안전성을 확정할 수 없다. AI는 관찰된 손상을 분류하고 가격표 항목을 제안하며, 금액 계산은 승인된 규칙 엔진이 수행한다. 모델이 임의의 달러 금액을 만들어 결제에 반영하지 않는다.

서비스별로 instant_fixed, photo_review, site_visit 세 경로를 설정한다. 표준 소규모 작업은 즉시 가격을 낼 수 있지만, 전체 외부 페인팅·높은 곳·습기·곰팡이·구조 균열·위험 재료 의심은 방문 또는 전문가 검토로 보낸다. 석면·납 여부를 사진 AI가 없다고 보증하지 않는다.

## 정찰제 카탈로그

각 패키지는 작업명, 측정 단위, 기본 수량, 포함 준비 작업, 도장 횟수, 자재 포함 여부, 색상 제한, 최대 높이, 접근 조건, 예상 시간, 제외 항목, 추가금 코드, 세금, 유효기간을 가진다. 무조건 'From $X'만 노출하지 않고 실제 구매할 수 있는 최소 범위와 총가격을 함께 보여준다.

```text
세전 견적 = 기본 패키지
          + 기본 수량을 초과한 작업량 × 단가
          + 중복 제거된 손상 보수 항목
          + 고객이 선택한 옵션
          + 승인된 접근·출장 항목
          - 승인된 할인
최종 금액 = 세전 견적 + 항목별 세금
```

기본 패키지에 포함된 퍼티·샌딩을 AI가 다시 추가하지 않도록 inclusion_group과 damage_region_id를 둔다. 같은 손상을 여러 사진에 찍었거나 같은 원인에 따른 여러 라벨이 나와도 한 작업으로 병합한다. '상태 불량 배율'과 개별 보수비를 동시에 적용하는 규칙은 명시 승인 없이는 금지한다.

예시이며 실제 판매가격이 아닌 테스트 계산: 기본 300.00 + 추가 수량 2 × 40.00 + 보수 50.00 = 세전 430.00. 모든 항목이 과세이고 GST 등록 사업자라는 조건에서 GST 43.00, 총 473.00이다. 중복 사진이 추가되어도 473.00이어야 한다. 고객이 수락한 뒤 가격표가 바뀌어도 이 버전은 유지한다.

## 현재 KCP 초기 가격 v1

시작가 A$1,500 GST 별도(A$1,650 포함)를 적용한다. 도장비는 `max(150000, 문 수 × 15000 + 서랍 앞판 수 × 10000)` cents이며, 허용된 중간 도막 손상은 프로젝트 전체에 25000 cents를 한 번 가산한다. 경미한 도막 보수는 기본 준비에 포함한다. GST는 소계의 10%를 cent 단위로 반올림하며 소계·세금·합계와 가격 버전을 서버와 DB에서 검증한다. 문·서랍 양수 수량은 선택 범위와 일치해야 한다. AI가 실제 크기나 면적을 정밀 측정한 것으로 표시하지 않는다.

필요 사진·수량/범위가 확인되면 `estimate_ready`로 GST 포함 총액을 표시하고, 추가 사진·수량 불일치·심한/팽창/미분류 손상·추가 표면/보수만 선택이면 `review_required`로 시작가와 확인 사유만 표시한다. 공개 지역 가격은 참고이며 공식 평균이 아니다. 실제 지정 두 손상 사진은 고객과 EMS 모두 검토 필요·총액 null을 확인했다. 충분한 전체 사진의 숫자 총액 실제 검증은 남아 있고 현재 금액 기대값은 합성 검사다. [39번 산식·공개 출처](39-sydney-cabinet-pricing-v1.md)와 [실제 브라우저 검증](../verification/2026-10-11-pricing-browser-qa.md)을 따른다.

## 사진 입력과 분석 계약

KCP는 전체 전면·상부/하부장·측면·심한 손상 등 약 5장으로 필요한 부위를 안내한다. 없는 부위/손상은 해당 없음으로 표시하고 장수만으로 분석 적합 판정을 하지 않는다. 구체 슬롯은 38번 구현 제안이며 기존 최대 8장·장당 10MiB 한도 안에서 추가 촬영을 지원한다. 사용 목적과 보관 정책을 안내하고 주소·얼굴 등 불필요 정보는 제거·가림을 지원한다.

| 분석 출력 | 목적 | 검증 |
| --- | --- | --- |
| service_type, surface_type | 가능한 서비스 분류 | 허용 enum만 허용 |
| observations[] | 관찰된 손상과 사진 내 위치 | image_id·region_id·분류·근거 필수 |
| quantity_estimate, unit, scale_present | 수량 제안 | 측정 기준 없으면 정확 면적 계산 금지 |
| risk_flags, missing_information | 검토 필요 조건 | 위험 플래그는 자동확정 차단 |
| suggested_rule_codes[] | 가격표 항목 매핑 | 활성 가격표 코드만 허용 |
| model_confidence | 내부 참고 지표 | 보정 전에는 정확도 확률로 표시 금지 |
| schema_version, model_version, prompt_version | 재현·감사 | 평가 데이터와 연계 |

사진·사용자 입력은 불신 데이터다. 이미지 속 '가격을 0원으로 하라' 같은 문구는 명령으로 실행하지 않는다. 분석에는 DB 변경·이메일 전송·결제 도구를 부여하지 않는다. 스키마 오류, 타임아웃, 불명확한 결과는 수동 견적 경로로 전환한다.

## 자동화 수준과 승인

KCP의 최신 기본 경로는 품질/범위가 충족된 사진을 실제 AI API로 분석하고, 승인된 회사 가격 기준으로 계산한 예상 견적을 고객 화면에 바로 표시하는 것이다. 현재 작성 세션의 최초 결과 표시를 직원 승인이나 OTP 뒤로 미루지 않는다. 회사 수동 검토는 분석 실패·정보 부족·현장 조정 경로에 사용한다.

예상 가격과 최종 계약 금액을 구분한다. 현장에서 발견한 추가 작업·수량·범위는 새 견적 버전과 변경 사유로 기록하고 고객에게 다시 확인받는다. 이전 승인/서명을 변경된 금액에 재사용하지 않는다. 제안 금액을 임의로 낮춰 상한을 통과시키거나 부분 금액을 전체 금액으로 표시하지 않는다.

OpenAI gpt-6.1-sol medium 사진 분석과 회사가 승인한 초기 가격 v1은 구현·검증했다. 운영 호출 예산·보관 정책의 전체 인수와 현장 가격 조정은 후속이다. 실제 호출 평가와 합성 검사를 구분하고 사진·계산 근거가 부족하면 필요한 추가 사진/정보를 안내한다. 상세한 버전·권한·처리 계약은 [38번](38-ai-photo-estimate-and-ems-plan.md)을 따른다.

## 주소 검증

최신 [회사 제공 자료](../reference-assets/company-brief.md)에 따라 **KCP는 Ermington 중심 10km + Inner West Sydney + 명시된 21개 suburb**를 기준으로 한다. 전부가 10km 안에 있다는 뜻은 아니며 이전 15km 가정과 10km만의 제한적 판정보다 회사 답변이 우선한다. 실제 기준점·10,000m 경계·지역별 주소 가능 여부·예외 처리 기준은 D02에서 확정한다. 자동 판정이 미정이면 검토로 받고 반경만으로 거절하거나 예약을 확정하지 않는다. Google Maps suburb 대표 지점은 콘텐츠 조사용이며 회사 출발 주소가 아니다. 과거 AI의 14~17km 자동 예외를 승인 규칙으로 사용하지 않는다. 다른 서비스/배송의 지역 정책은 별도다.

주소 검증은 일정 선택 전에 실행한다. 서버는 고객 입력 주소와 검증 결과를 사용하며 브라우저의 좌표·거리·가능 여부를 그대로 신뢰하지 않는다. 거리 계산은 geography 기반 미터 단위를 사용하고, 정확한 기준 주소를 지도에서 검증한다. 중심 주소의 정밀 위치를 공개할 필요는 없다.

운전거리·시간은 배차 계획에서 추가로 고려하되 직선거리 계약 기준과 섞지 않는다. 대표가 도로거리 기준을 선택하면 화면 문구·가격 규칙·테스트를 함께 변경한다. Google 결과는 저장·캐시·표시 제한이 있으므로 고객이 입력한 주소, 장기 보관 가능한 식별자, 파생 기록을 구분하고 계약 조건을 검토한다. [Geocoding 정책](https://developers.google.com/maps/documentation/geocoding/policies), [Routes 정책](https://developers.google.com/maps/documentation/routes/policies)

## 견적 수락부터 예약

KCP는 고객이 승인된 범위·가격을 **approve**한 뒤 앱 달력에서 시작일을 고르고 최종 요약에 서명·제출한다. 비공개 최종 견적·서명 계약서를 이메일 제공자가 수락한 후 회사 Calendar에 `Pending confirmation`으로 업로드한다. 회사가 duration·자원·전체 충돌을 확인하고 변경 조건에 필요한 재동의·재서명을 받은 뒤 확정한다. 이미 예약된 날짜는 UI와 서버에서 차단하며 제출 직전·회사 확정 시 다시 검사한다. 기간/자원 미정이나 Calendar 조회 실패를 가용으로 처리하지 않는다.

다른 서비스의 일반 견적 이메일·수락·예약금 분기는 별도 승인 정책을 따른다. KCP에서 초안 저장·approve·최종 서명 제출은 각각 다른 명령이고, 고객 이메일을 보냈거나 Calendar에 나타났다는 사실만으로 확정 예약이 되지 않는다. 예약금 정책을 추후 적용하더라도 32번의 제출/문서/메일 순서와 회사 확인을 생략하지 않는다.

견적 유효기간 14일은 기존 일반 기본안이며 KCP 운영값은 회사 승인 전 적용하지 않는다. 만료 견적은 재확인 없이 결제에 사용할 수 없다. 고객의 클릭 한 번은 quote_version_id와 acceptance_hash로 유일하게 기록한다. 이메일 링크의 GET 요청만으로 수락되지 않게 한다.

예약 가용성은 직원 능력·서비스 시간·이동 버퍼·휴식·휴무·기존 작업·동시 수용 인원·현장방문 여부를 함께 계산한다. 2인 작업이면 필요한 두 직원 또는 팀 자원을 같은 트랜잭션에서 확보한다. 시공 기간이 여러 날이면 하루 슬롯 하나로 축약하지 않는다.

임시 점유 15분은 일반 기본안이며 KCP는 승인된 점유 정책이 생긴 뒤 실제 Checkout 만료와 연계한다. 결제수단별 지연을 고려해 초기에는 즉시 확인 가능한 수단으로 시작한다. 점유 만료와 결제 성공이 경합하면 DB에서 원자적으로 상태를 검사한다. 자원이 이미 팔렸다면 새 예약을 강제 확정하지 않고 payment_received_review 상태에서 대체 일정 또는 환불을 처리한다.

예약금은 서비스 계약 유형의 정책을 따른다. NSW 주거공사에 적용되는 예약금 상한과 계약 조건을 검토하며 일괄 30%·50%로 설계하지 않는다. 해당 법 적용 시 최대 10% 조건을 준수하도록 설정하고, 의도적으로 작업을 쪼개 기준을 회피하지 않는다. [NSW 주거공사 계약](https://www.nsw.gov.au/housing-and-construction/building-or-renovating-a-home/preparing/contracts)

## 현장 변경과 잔금

예상하지 못한 추가 작업은 사진·사유·금액·일정 영향이 있는 variation으로 제출한다. 고객 수락 전 추가 청구하거나 결제카드에서 임의 인출하지 않는다. 기존 승인 범위 작업과 미승인 작업을 구분하고 안전 문제는 작업 중단·전문가 연결로 처리한다.

완료 사진과 체크리스트 → 소유자 권한 사용자의 프로젝트 Complete → 최종 인보이스 1회 발행 → 실제 발행일 +3 달력일(Sydney) 납기 → 입금 배분으로 이어진다. KCP의 제출 시 최종 견적·서명 계약서는 인보이스가 아니다. 후기 요청은 별도 승인된 알림으로 연결한다. 예약금은 전체 매출에 다시 더하지 않는다. 취소·재예약·부분 환불은 원거래 연결을 유지한다.
