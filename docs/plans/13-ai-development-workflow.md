# 모델 선택과 개발 운영

## 주 채팅의 사용자 선택과 기본값 — 2026-10-06

사용자가 앱이나 실행 옵션에서 명시적으로 선택한 주 채팅의 모델과 reasoning effort를 따른다. 별도 선택이 없는 Mac 공통 기본값은 `gpt-6-astra` / `medium`이다. 실제 기본값은 `~/.codex/config.toml`에서 확인하며, 전역 기본값은 사용자의 명시적 선택을 제한하지 않는다.

프로젝트의 [.codex/config.toml](../../.codex/config.toml)에는 주 채팅의 모델·effort를 고정하지 않는다. 업무나 커스텀 역할을 선택했다는 이유로 주 채팅의 모델이 자동 전환됐다고 설명하지 않는다.

2026-10-01의 사용자 선택 정책은 주 채팅에 유지한다. 최신 공통 지침에 따라 아래 세 커스텀 서브에이전트에는 승인된 모델·effort 명시값을 적용하고, 그 밖의 별도 지정이 없는 에이전트에는 상속 규칙을 적용한다. 과거 업무별 강제 분업이나 모든 채팅의 `xhigh` 고정 의무를 다시 도입하지 않는다. Sol 모델 표기는 `gpt-6.1-sol`로 사용하며 과거 실제 실행 모델을 적은 검증 기록은 당시 사실대로 보존한다.

## 승인된 커스텀 서브에이전트

공통 정책의 원본은 `~/.codex/AGENTS.md`이며, 역할별 실제 설정은 다음 TOML을 기준으로 확인한다. [프로젝트 지침](../../AGENTS.md)에도 동일한 역할 구분을 적용한다.

| 역할 | 모델 | reasoning effort | 설정 파일 | 담당 업무 |
| --- | --- | --- | --- | --- |
| `analyst` | `gpt-6-astra` | `xhigh` | `~/.codex/agents/analyst.toml` | 요구사항·설계·대안·위험, 리뷰·QA, 테스트 전략·실패 원인·결과 판정, UI/UX·접근성, 복잡한 구조 판단 |
| `implementer` | `gpt-6.1-sol` | `high` | `~/.codex/agents/implementer.toml` | 확정 설계의 파일·순서별 구현 계획, 코드·일반 버그 수정·리팩터링, 테스트 작성·실행과 일반 실패 수정 |
| `quick_edit` | `gpt-6-luna` | `high` | `~/.codex/agents/quick_edit.toml` | 정답과 범위가 명확한 저위험 코드·CSS·색상·간격·문구·숫자 변경과 직접 관련된 검증 |

세 역할을 선택해 실행할 때는 해당 커스텀 에이전트 TOML의 모델·effort를 사용한다. 예를 들어 주 채팅이 Astra / `medium`이어도 `analyst`는 Astra / `xhigh`, `implementer`는 Sol / `high`, `quick_edit`는 Luna / `high`로 실행하도록 정의돼 있다. 별도 지정이 없는 다른 서브에이전트·커스텀 에이전트는 현재 채팅의 모델·effort를 상속한다. [공식 서브에이전트 설정 안내](https://learn.chatgpt.com/docs/agent-configuration/subagents)

이 전역 역할 파일은 프로젝트 저장소에 포함되지 않는다. 다른 기기에서는 해당 기기의 전역 지침·기본값·역할 파일과 클라이언트 지원 여부를 별도로 확인한다. 파일이 존재한다는 사실과 클라이언트가 역할을 로딩했다는 사실, 지정 모델로 실제 실행에 성공했다는 사실을 구분한다.

## 위임과 역할 전환

- 서브에이전트는 사용자의 직접 요청이나 적용되는 프로젝트·스킬 지침이 허용하는 범위에서 사용한다. 역할 정의가 있다는 사실만으로 매 작업마다 위임하지 않으며, 작은 작업에 세 역할을 모두 호출하지 않는다.
- 변경 줄 수보다 판단 난도와 영향 범위로 분류한다. 결제·권한·데이터에 영향을 주는 변경은 숫자 하나라도 `quick_edit`로 분류하지 않는다.
- 반응형 구조나 UX 판단이 필요하면 `analyst`가 분석하고 `implementer`가 구현한다. 테스트 전략과 결과 판정은 `analyst`, 테스트 구현·실행과 일반 실패 수정은 `implementer`가 담당한다.
- `quick_edit`의 범위가 커지면 `implementer`로, 새로운 설계나 복잡한 구조 판단이 필요하면 `analyst`로 상향한다. 역할 전환으로 사용자 승인 범위를 확장하지 않는다.
- 주 에이전트는 역할마다 작업 범위·산출물·파일 소유 범위를 나누고 결과를 통합·검증한다. 같은 파일의 편집은 순차적으로 수행한다.
- 각 역할은 사용자의 현재 요청과 파일 수정·실행 제한을 따른다. 커밋·푸시·배포·게시·외부 메시지 전송은 해당 작업의 승인 범위를 별도로 따른다.

## 스킬 적용

사용자가 스킬 이름을 입력하지 않아도 작업 목적·자료·원하는 결과·단계·환경에 맞는 활성 스킬을 선택한다. 적용할 스킬의 지침과 필요한 참조만 읽고, 처음 적용할 때 이름과 목적을 짧게 알린다. 명시적 요청 전용 스킬이나 비활성 스킬의 제한을 존중한다.

역할이 겹치는 스킬의 계획·검토·검증을 반복하지 않으며 작업 규모에 맞게 적용한다. 스킬 선택이나 역할 위임만으로 승인 범위가 넓어지지 않는다.

## 적용 범위와 한계

파일 수정만으로 진행 중인 대화의 실행 모델이 바뀌지는 않는다. 사용자는 앱의 모델 선택 메뉴 또는 명시적인 실행 옵션으로 실제 모델을 선택한다. 실행 모델·effort를 확인할 수 없는 경우 확인했다고 주장하지 않는다.

공통 사용자 선호는 `~/.codex/AGENTS.md`에 저장한다. Codex는 실행 시작 시 전역 지침과 프로젝트 지침을 읽으므로 이미 열린 다른 채팅에 즉시 다시 로드됐다고 보고하지 않는다. 프로젝트 설정은 클라이언트의 설정 우선순위와 프로젝트 신뢰 상태에 따라 적용된다. [공식 전역 지침 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [설정 우선순위](https://learn.chatgpt.com/docs/config-file/config-basic)

계정·클라이언트·워크스페이스에서 지원하는 모델만 선택할 수 있다. 설정 파일은 모델 접근 권한을 추가하지 않는다. 지정 모델이 unavailable이거나 역할 로딩·상속·지정이 불가능하면 조용히 다른 모델로 대체하지 않고 제한을 사용자에게 알린다. 주 에이전트는 무관한 작업을 가능한 범위에서 계속한다. 별도의 AI 사진 분석 API에서 채팅과 같은 모델 ID를 사용할 수 있다고 가정하지 않으며 사진용 모델은 지원·비용·평가를 따로 확인한다.

## 작업 인계와 검증

구현 전 요구사항 ID, 설계·불변 조건, 범위, 예외, 인수 기준을 정리한다. 구현 후 변경 파일·실행한 검증·결과·남은 문제를 기록한다. 검토는 실제 코드·실행 결과·재현 증거를 기준으로 수행하고 실패하면 원인과 수정 범위를 좁힌다.

모델 이름이 검증 품질을 보장하지 않으므로 결과 증거가 필요하다. 검증 결과를 만들어내거나 미실행 테스트를 통과로 표시하지 않는다. 확인할 수 있는 경우에만 실제 선택 모델·effort를 기록하며, 고객에게 보여주는 제품 화면에는 내부 모델 선택을 노출할 필요가 없다.
