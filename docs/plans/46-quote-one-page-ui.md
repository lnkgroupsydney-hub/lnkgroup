# 견적 원페이지 UI·UX 개선

2026-10-13 · Australia/Sydney · `codex/quote-one-page-ux-20261013`

사용자 요청: 새 브랜치에서 스크롤로 단계 이동하는 견적 화면을 원페이지로 변경하고, 강조와 시각적 구조·사진 분석 로딩·전체 주소 자동완성을 구현하며 테스트 문구를 제거한다.

## 디자인 분석과 구현

기존 Slate/Greige·Manrope·사업 가격 및 저장·인증·예약 계약을 유지한다. 기능 명세는 [45번 예약 절차](45-simple-take-off-install-booking.md)를 따른다. 고객이 날짜·시간을 선택하고 한 번 서명·제출하며 회사가 installation 방문을 배정·확정한다.

| Before | After | Why |
| --- | --- | --- |
| 인증·상세·사진·분석·달력·서명이 세로로 누적 | 고객 정보 → 캐비넷 → 사진 → 예상 금액 → 방문일 → 서명, 접수 완료의 개별 패널 | 다음 단계로 스크롤할 필요를 없애고 현재 과업을 분명히 한다 |
| 텍스트 진행 목록·동일한 선택 행 | 아이콘 단계 표시·선택 상태 카드·고정 하단 액션 | 진행 상황과 다음 동작을 즉시 알 수 있다 |
| 예상 금액과 확인 안내가 본문에 섞임 | GST 포함 금액 강조·현장 확인 안내·접힌 가격/범위 내역 | 금액과 제한을 우선 읽을 수 있다 |
| 촬영 안내와 분석 대기 문장 | 캐비넷 촬영 역할 그림·비공개 사진 카드·실제 queued/running 로딩 | 사진 준비와 분석 대기를 이해하기 쉽다 |
| 이메일 관리 UI가 초기 폼 앞에 펼쳐짐 | 별도 이메일 관리 패널, 인증 후 동일 요청의 이전 단계로 복귀 | 첫 입력 부담과 단계 손실을 줄인다 |
| 접수 정보와 발송 안내가 긴 목록으로 나열 | 금액·희망 방문일·접수번호 강조, 상세 접수 정보는 펼쳐 보기 | 접수 결과를 빠르게 확인할 수 있다 |
| 공개 Preview·Draft·내부 확인 메모 | 실제 견적·예약 흐름 설명 | 테스트용 안내를 제거하며 생성 이미지의 사실 고지는 유지한다 |

문서 전체는 고정된 화면 영역에 있으며 각 패널의 긴 내용만 내부 스크롤한다. 320px·모바일에서도 하단 동작과 입력에 접근할 수 있다. 단계 이동은 `focus({preventScroll:true})`와 패널 내부 상단 초기화를 사용한다. 비활성 패널은 `hidden`으로 탭·접근성 트리에서 제외한다.

## 보존하는 경계

- 사진/예약/이메일 상태 소유자를 단계 이동으로 unmount하지 않는다. 고객 identity·요청 변경 시 비공개 상태는 폐기한다.
- 미저장 고객·서비스 변경은 저장/버리기 전 다른 단계·분석·서명으로 진행할 수 없다. 늦은 사진 조회는 dirty 입력을 덮지 않는다.
- 가입 이메일 일치뿐 아니라 요청별 연결·현재 요청 검사를 유지한다. 인증 복구는 동일 요청이면 인증 전 단계로 돌아간다.
- 승인·선택·review 자동 저장 및 revision·proof·idempotency body는 기존 계약을 따른다. 날짜/시간 변경·만료는 서명을 폐기한다. 비활성 화면의 proof 만료는 현재 입력/이메일 패널을 강제로 닫지 않는다.
- 숨은 예약 최초 조회 실패가 전체 작성 화면을 영구 잠그지 않는다. 실패한 분석은 회사 검토 요청으로 진행할 수 있으며 숫자 견적 없는 날짜 선택은 계속 차단한다.
- 사진 분석은 실제 준비·queued·running 상태만 표시한다. 임의 진행률이나 소요시간을 만들지 않으며 동작 줄이기 설정을 지원한다.

## Google 주소

현재 고객 Quote·기존 draft·enquiry 각각 street/suburb/postcode 3개와 EMS 고객 단일 주소 1개, 총 **10개 입력**이 공통 Google Places (New) combobox를 사용한다. 선택한 단일 고객 주소는 기존 단일 텍스트 저장 계약을 유지한다. AU 제한·세션 토큰·필드 최소화·오래된 응답 폐기·키보드/IME·수동 fallback을 보존한다.

사용자가 **회사 API 키·결제 준비가 아직 필요함**을 확인했다. `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`가 없어 실제 Google 검색은 미실행이다. 회사 Google Cloud의 Maps JavaScript API·Places API (New)·결제, 회사 도메인/로컬 referrer 제한 키 설정과 재빌드 뒤 실제 dropdown 인수를 진행한다. 새 회사/개인 Cloud 리소스·유료 약정을 생성하지 않는다. [주소 연결 계획](34-google-address-autocomplete.md)을 따른다.

## 검증과 전달

코드 검사와 로컬 브라우저 인수는 [검증 기록](../verification/2026-10-13-quote-one-page-ui.md)에 구분한다. 브라우저는 실제 Quote API/PGlite 저장을 사용하며 auth·사진·AI·예약 응답만 합성 공급한다. 운영 DB·AI·메일·Calendar 변경·운영 배포·commit·push·merge는 이번 작업에 포함하지 않는다.
