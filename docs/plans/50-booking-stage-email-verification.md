# 방문 날짜 단계의 단일 이메일 인증

2026-10-13 · Australia/Sydney

사용자 요청: 이메일 검증은 booking date 단계에서 한 번만 진행한다. 신규 작성 후 인증 화면에서 예약 중인 이전 견적이 나타나는 혼동을 분석하고 새 견적 진입 아이디어를 제시한다.

## 구현 범위

신규 작성은 연락처 → 캐비넷 → 사진/분석 → 예상 금액까지 guest 작성 권한으로 진행하며 방문 날짜 단계에 현재 견적의 이메일 인증을 모은다. 이메일 세션·요청별 연결·현재 선택 요청이 모두 일치하면 추가 코드를 보내지 않는다. 만료·회수·다른 기기 복구는 기존 재인증 경계를 유지한다. 인증을 영구 승인으로 바꾸지 않는다.

| Before | After | Why |
| --- | --- | --- |
| 저장/복구 화면에 일반 이메일 로그인과 현재 견적 연결 버튼이 함께 표시 | 방문일 화면은 현재 저장 이메일·request ID·revision에 묶인 단일 인증 | 코드 한 번으로 현재 작성본을 연결 |
| 인증 완료 후 전체 연결 견적 목록을 항상 표시 | 방문일 인증은 날짜 화면으로 복귀, 목록은 명시적 Open saved quote에서만 표시 | 작업 대상을 유지 |
| 다른 탭의 인증 알림이 현재 초안을 지우고 선택된 요청을 자동 복원 | 알림은 인증 메타데이터를 재조회하고 현재 작성/선택 상태를 대조 | 편집 중 자료를 다른 요청으로 덮어쓰지 않음 |
| 인증 후 같은 요청에도 상세/분석을 초기화 | 같은 ID 인증은 현재 상세·분석·방문 단계 보존, 예약 접근 상태만 재확인 | 인증 완료 뒤 흐름을 계속 진행 |

OTP 완료 결과가 예상 request ID와 다르면 해당 견적을 복원하지 않는다. 인증 대기 중 요청·revision 변경과 늦은 응답을 검사한다. 기존 일반 이메일 복구·이전 사이트 handoff·직원 인증·저장 재시도·서명/예약 권한은 유지한다.

같은 이메일의 다른 탭에서 현재 선택이 바뀌면 작성값을 보존하면서 전송을 잠근다. 이미 본인에게 연결된 현재 견적은 명시적인 **Continue this quote**로 기존 select API를 호출해 다시 선택할 수 있다. 이 동작은 입력·단계·분석을 복원값으로 덮어쓰지 않으며 자동 선택이나 새 OTP를 추가하지 않는다.

현재 서버는 bound OTP 완료로 특정 견적을 연결하며 일반 이메일 로그인은 currentRequestId=null이다. 이메일 문자열만으로 견적을 자동 연결하지 않는다. 로그인한 상태에서 다른 unlinked guest 요청을 OTP 없이 연결하는 기능은 없으므로 새 RPC/DB/운영 정책을 이번 UI 수정에 포함하지 않는다.

## 새 견적 진입 제안

권장안은 시작 화면에서 **Start a new quote**와 **Continue a saved quote**를 분리하는 것이다. 신규 선택은 기존 예약·사진·서명을 보존하며 새 요청 ID를 만든다. 복귀 선택만 연결된 견적 목록을 연다. 날짜 단계에서 새 요청을 이메일에 연결해도 이전 예약 화면으로 자동 이동하지 않는다.

추가로 기존 고객은 본인 확인된 이름·이메일·전화만 새 견적에 미리 채우고 주소·캐비넷·사진·일정은 새로 입력하게 할 수 있다. 로그인 유지 상태에서 새 요청을 시작하고 기존 세션으로 연결하는 방식은 guest/customer 선택 우선순위와 서버 권한을 설계·검증해야 하는 후속 구현이다.

현재 앱의 새 견적 기능은 연결·저장 확인 뒤 고객 견적 접근을 로그아웃하고 빈 작성 세션을 여는 방식이다. 기존 요청은 보존된다. 이번에는 이 동작을 삭제하거나 로그인 유지 정책으로 바꾸지 않으며 위 진입 구조는 사용자에게 제안한다.

## 검증

로컬 fixture로 초기 단계 이메일 발송 0건, 방문일 bound OTP 1회, 인증 후 현재 ID/분석 유지, 유효 연결 세션 재인증 없음, 이전 요청 목록 자동 열림 없음, 다른 탭/늦은 응답·만료 및 기존 예약 회귀를 확인한다. 실제 회사 DB·인증 메일·Google·AI와 운영 배포는 별도다. 구현 후 실행 결과는 검증 기록에 남긴다.

구현과 로컬 검증 완료: 전체 **749/749**, 관련 최종 **21/21**, lint·타입·build와 공개 브라우저 **18/18** 통과. [검증 기록](../verification/2026-10-13-booking-stage-email-verification.md)에 footer 자동 저장·달력 읽기 중단·pending review 복구의 재현/수정과 실제 제공자 미실행을 구분했다. 새 견적 진입 구조/로그인 유지 API는 제안으로 남는다.

Supabase OTP/세션 문법은 [공식 이메일 인증 문서](https://supabase.com/docs/guides/auth/auth-email-passwordless)를 확인했다. 기존 제공자 API와 DB 계약은 변경하지 않는다.
