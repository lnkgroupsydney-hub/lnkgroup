## 1. 결정과 가격의 성격

사용자가 **시작가 A$1,500 GST 별도**를 확정했다. 문 A$150·서랍 앞판 A$100·중간 도막 보수 A$250은 이번 구현에서 승인한 L&K 초기 예상 알고리즘이다. 지역 사업자의 공개 가격을 참고했지만 **검증된 Sydney 시장 평균이나 현장별 확정 견적을 뜻하지 않는다**. 사용자는 사진으로 예상 작업과 가격을 확인하며, 실제 상태·범위 확인 후 변경될 수 있다. 예상 견적 열람은 계약·서명·결제·예약 확정이 아니다.

가격 버전은 `lk-sydney-cabinet-v1-20261011`이다. AI는 사진에서 보이는 상태·손상·수량·작업 후보를 분석하고, 서버의 순수 가격 계산기가 금액을 만든다. AI 생성 달러 금액, 고객 제출 합계, 과거 데모 A$1,250은 계산 입력으로 사용하지 않는다.

## 2. 초기 산식과 포함 범위

| 항목 | GST 별도 기준 | 적용 |
| --- | --- | --- |
| 최소 도장비 | A$1,500 | 문·서랍 도장 항목 합계의 최소값. 문/서랍 단가에 기본비를 다시 더하지 않음 |
| 캐비넷 문 | 1개 A$150 | 일반 준비·도장 및 경미한 도막 보수 포함 |
| 서랍 앞판 | 1개 A$100 | 일반 준비·도장 및 경미한 도막 보수 포함 |
| 중간 도막 보수 | 프로젝트당 A$250 | 허용된 중간 손상이 있으면 한 번. 사진/손상 관찰 수만큼 반복하지 않음 |
| GST | 소계의 10% | cents 단위로 반올림 |

```text
도장비 = max(A$1,500, 문 수 × A$150 + 서랍 앞판 수 × A$100)
소계 = 도장비 + (중간 도막 보수 필요 시 A$250, 아니면 A$0)
GST = 소계의 10%를 cent 단위로 반올림
예상 총액 = 소계 + GST
```

최소금액 보정은 `minimum_adjustment` 항목으로 분리하고 실제 문/서랍 수량·단가를 유지한다. 통화는 AUD, 저장 단위는 정수 cents(`amountUnit: cents`), `minimumSubtotal: 150000`, `gstRateBps: 1000`이다. 부동소수 달러 값을 저장하지 않는다.

| 합성 산식 예시 | 소계 | GST | 예상 총액 |
| --- | --- | --- | --- |
| 문 5개 + 서랍 앞판 2개, 일반 준비 | A$1,500 | A$150 | A$1,650 incl GST |
| 위 수량 + 허용된 중간 도막 보수 | A$1,750 | A$175 | A$1,925 incl GST |
| 문 10개 + 서랍 앞판 3개, 일반 준비 | A$1,800 | A$180 | A$1,980 incl GST |

위 예시는 산식 확인용 합성 입력이다. 실제 사용자 사진에 대한 금액이나 완료된 현장 견적이 아니다.

## 3. 총액을 보류하는 조건

정상 결과 `estimate_ready`는 분석이 `analysis_ready`이고 필요한 사진과 수량·범위가 확인된 경우에만 만든다. 전체 전면·하부/서랍·측면이 근거 사진으로 보여야 하며 사진이 usable이어야 한다. 저장 서비스 수량, 분석의 고객 수량과 관찰 수량이 같고 확인 필요 표시가 없어야 한다. 양수 문/서랍 수량은 해당 표면 선택과 일치해야 한다.

아래 경우는 `review_required`로 작업 설명·구체적 확인 사유를 저장한다. `lineItems`는 빈 배열, 소계·GST·총액은 모두 null이다.

- 추가 사진 또는 현장 검토가 필요한 분석, 흐린/사용 불가 사진, 전체 전면·하부·측면 범위 누락.
- 수량 미확인·불일치·0개 전체 범위, 문/서랍 수량이 있는데 해당 표면을 선택하지 않은 경우.
- 전면 도장/색상 변경 외 의도, 프레임·끝판·불명 범위 또는 보수만 선택한 경우.
- 심한 손상, 팽창·벌어짐·구조 문제나 분류되지 않은 손상. 교체·구조 보수는 이 단가에 포함하지 않음.

재질·실제 크기·도막 부착·숨은 손상은 현장 확인 사항이다. v1이 이러한 항목을 정밀 실측했다고 표시하지 않는다. 적은 근접 손상 사진 두 장만으로 전체 프로젝트를 확인하거나 자동 총액을 보장하지 않는다.

## 4. 고객·EMS 표시와 과거 결과

고객과 EMS는 같은 `SavedPhotoAnalysis`와 같은 저장 가격 버전을 읽는다. 정상 결과에는 **GST 포함 예상 총액을 먼저 강조**하고 항목·수량·GST 별도 단가·금액·소계·GST·총액을 표로 보여준다. 시작가는 **A$1,650 incl GST (A$1,500 + GST)**로 안내한다. GST 포함 전체 가격을 소비자가 명확히 볼 수 있도록 표시하는 원칙을 반영했다. [ACCC 가격 표시 안내](https://www.accc.gov.au/consumers/pricing/price-displays)

`review_required`는 시작가만 보여주고 “이 요청의 총액은 아직 산정되지 않음”과 보완 사유를 함께 표시한다. 시작가나 부분 금액을 전체 예상 총액으로 표시하지 않는다. 현장 확인 후 범위·가격 변경 가능 및 계약/예약 미확정 안내는 가격 옆에 둔다.

이전 `pricingVersion: unconfigured`·`status: awaiting_company_rates` 결과와 금액 null은 역사적 저장본으로 유지한다. 새 규칙으로 재해석하거나 덮어쓰지 않고 당시 가격 설정 대기 결과라고 표시한다. 사진·수량·서비스가 바뀐 분석은 stale 표시와 새 분석 안내를 유지한다.

서버와 고객 응답 파서는 `validateEstimatePricing`로 상태·통화·버전·단위·항목별 곱셈·최소 보정·중복 항목·세금·합계를 검사한다. 금액 수정이나 상태 불일치를 타입 단언만으로 수락하지 않는다. 저장 계약은 새 가격과 과거 대기 형식을 함께 지원한다.

## 6. 실행된 검증과 남은 인수

가격 산식·최소 보정·중간 보수 한 번·심한/부족/범위 예외·표면/수량 일치·저장 형식·금액 변조·과거 결과 보존과 고객/EMS 공유 결과 렌더 검사를 포함해 전체 자동 테스트 **488/488**이 통과했다. `npm run check`의 lint·타입 검사·production build도 통과했다. UI 담당의 파서/React 정적 렌더 검사는 **12/12** 통과했다.

새 가격 적용 뒤 회사 Chrome에서 실제 두 손상 사진 업로드 → AI 분석 → 추가 확인/금액 보류 표시 → 새로고침 복원 → EMS 동일 저장 결과 확인을 완료했다. 실제 분석은 `additional_photos_required`, 가격은 `review_required`/총액 null이다. 키보드 Tab/Return 분석 시작과 320px 모바일 메뉴 열기/닫기·가격/결과 줄바꿈을 확인했고 콘솔 오류는 0건이었다. 사진 입력의 name 보완 후 최신 `npm run check`도 재통과했다. 새 SQL 적용·익명 접근 차단과 실제 결과는 [가격 브라우저 검증](../verification/2026-10-11-pricing-browser-qa.md)을 따른다.

전체 범위와 확정 수량이 확보된 실제 사진의 **정상 숫자 총액 인수는 대기**한다. 자동 검사와 실제 두 사진의 추가 확인 경로 성공을 정상 금액·전체 분석 품질 검증으로 합치지 않는다. 실기기 사진/경계 검증과 운영 공개 인수도 별도다.
