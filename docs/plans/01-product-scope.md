# 사업 목표와 구현 범위

**2026-10-02 KCP 고객 흐름:** [32번 최신 계약](32-client-quote-signature-submission.md)의 고객 정보·디테일 저장 → 서비스/사진 → AI/승인 가격 → 고객 approve → 앱 달력 → 최종 확인/서명/제출 → 최종 견적·서명 계약 이메일 → 회사 Google Calendar 순서를 적용한다. 고객 제출은 예약 요청이며 회사 기간·충돌 확인 후 확정한다. 이미 예약된 날짜는 선택을 차단하고 서버에서도 재검사한다. KCP 실행 순서는 [25번](25-kcp-quote-to-booking-implementation.md), 실제 완료 상태는 [15번 TODO](15-home-cabinet-admin-todo.md)를 우선하며 다른 사업의 범위를 확대하지 않는다.

## 사업 목표

고객은 자신의 지역에서 가능한 서비스와 예상 비용을 빠르게 파악하고, 견적을 확인한 뒤 예약하거나 상품을 구매할 수 있어야 한다. 운영자는 동일 고객의 문의·견적·작업·주문·입금·재고를 한 화면에서 추적하고, 예외 상황만 직접 처리한다.

전체 목표는 5개 사업을 모두 지원하는 것이다. 출시를 나누는 이유는 서비스 원가, 온라인 구매, 식품 물류, AI 판단을 각각 검증해야 하기 때문이다. 초기 유료 매출을 만드는 최소 기능과 전체 사업 확장을 구분한다.

## 사용자와 핵심 업무

- 방문자: 로그인 없이 서비스·상품·정책 확인, 주소 확인, 견적 신청, 비회원 구매.
- 고객: 이메일 인증 후 본인 견적 approve·최종 확인/서명/제출, 예약 변경 요청, 주문 추적, 견적·계약서·인보이스 열람.
- 운영 관리자: 신규 문의 처리, 견적 승인, 직원·시간 배정, 공급·재고·출고, 고객 응대.
- 현장 직원: 배정된 작업 주소·연락처·범위, 진행 상태와 사진 업로드. 전체 매출·고객 목록은 접근 불가.
- 식품 출고 담당자: 본인 업무에 필요한 주문·배송·배치 정보. 시공 사진 접근 불가.
- 회계 담당자: 인보이스·입금·환불·세금 구분·CSV. 원본 주거 사진은 기본 접근 불가.
- 대표: 사업별 수익, 미수금, 예약 능력, 원가·가격 변경 승인, 사용자 권한 관리.

## 초기 범위 상한

초기 산정은 단일 판매 법인, 관리 장소 1개, 운영 사용자 10명 이하, 서비스 상세 8개, 상품 기본 SKU 20개 이하, 월 서비스 문의 300건·상품 주문 300건 수준을 가정한다. 이는 수용능력 보장이나 실적이 아니라 일정 산정 조건이다. SKU 옵션·이미지·재고는 이 한도 안에서도 모두 구현한다.

8개 서비스 후보는 실리콘 재시공, 문 조정·수리, 방충망 교체, 벽걸이, 타일 부분교체, 내부 페인팅, 외부 페인팅, 캐비넷 페인팅이다. 자격 검토에서 제외된 항목은 대체한다. 전체 페인팅과 복잡한 캐비넷은 방문 견적을 기본으로 한다.

첫 버전에서 제외할 것은 급여·근태·BAS 신고·회계 총계정원장, 직원 소셜 피드, 다판매자 마켓플레이스, 다창고 최적화, 구독 자동결제, 전국 냉장 배송, 네이티브 모바일 앱이다. ERP는 주문·재고·작업·수금에 집중하고 세무 회계는 기존 회계 도구에 연결한다.

## 사업 지표

초기 4주 동안 기준값을 측정하고 목표를 재설정한다. 제안 목표는 유효 문의 영업시간 내 1영업일 이내 대응 95%, 예약 중복 0건, 중복 결제 0건, 금액 불일치 0건, 주문 재고 정확도 99% 이상이다. 서비스 견적 수락률과 상품 구매 전환율은 [마케팅 계획](11-marketing-and-growth.md)의 가설로 관리한다. 예약을 늘리는 성과와 수익이 남는 성과를 별도로 본다.
