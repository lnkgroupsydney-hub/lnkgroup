# 날짜·시간·서명 1회와 EMS 단일 예약 확정

2026-10-13 · Australia/Sydney · `codex/quote-date-first-flow-20261013`

## 이번 사용자 결정

**고객:** 사진 예상 견적 → take-off 날짜·시간 선택 → 서명 → 제출.

**EMS:** 사진·예상 견적 확인 → 현장 손상이 사진보다 크면 금액 증가 가능 안내/회사 안내 추가 → 고객이 선택한 take-off 시작 확인 → install 일시 선택 → **Booking confirm 한 번** → 고객 확정 이메일·회사 Google Calendar 자동 저장.

새 요청은 회사 제안 발행·고객 두 번째 온라인 서명·확인본 메일을 기다리는 왕복을 요구하지 않는다. 최초 서명에서 회사의 설치일 배정과 현장 확인 후 금액 조정 안내를 함께 확인한다. 예약은 계약·작업 지시·추가금 자동 결제와 구분한다.

## 입력과 처리

- 고객은 가능한 날짜와 `HH:mm` 시드니 시간을 직접 선택한다. 승인 snapshot 생성·날짜/시간 저장·서명 대상 검토는 내부 명령으로 처리한다. 고객에게 별도 승인/저장/검토 버튼을 순서대로 요구하지 않는다.
- 날짜 또는 시간을 바꾸면 서명 검토 hash와 선택 revision이 바뀐다. 변경 전 증명으로 제출할 수 없다. 이메일 소유 인증·비공개 저장·최신 사진/AI/가격 검증은 유지한다.
- EMS의 take-off 시작은 서명된 고객 입력에서 읽으며 수정할 수 없다. 회사가 take-off 종료와 install 시작·종료를 한 화면에서 입력한다. Google 충돌 검사에 필요한 실제 기간이며 기본 근무시간·1시간 등의 소요시간을 임의로 채우지 않는다.
- 이번 간소화 경로의 금액은 고객에게 표시된 원본 사진 예상 견적 그대로다. 현장에서 손상·범위가 추가 확인되면 추가 작업·비용을 진행 전에 안내한다. 서명하지 않은 추가금을 최종 합의 금액으로 표시하지 않는다.
- `Booking confirm`은 두 작업 구간의 최신 Google/DB 충돌을 확인하고 불변 예약 자료·점유·외부 작업을 함께 저장한다. 고객이 설치일을 다시 온라인 승인해야 확정되는 조건은 새 경로에 없다.
- 같은 버튼의 자동 처리 내부 순서는 **DB 점유 → take-off/install Google 일정 저장·각각 독립 조회 → 예약 confirmed → 확정 메일**이다. Google 저장이 실패했는데 고객에게 성공 메일이 가는 상황을 막는다. 고객·회사에 추가 클릭은 요구하지 않는다.
- 새 v2 최초 제출은 EMS 접수와 PDF/안내 메일로 저장하며 Google 대기 일정을 만들지 않는다. Calendar 작업 두 개는 EMS 예약 확정 후 저장한다. 접수 안내는 추가 승인 요청이 아니다.
- 두 방문 사이의 모든 날짜를 자동 점유하지 않는다. 기존 확정 작업이 조금이라도 있는 날은 현재 정책대로 고객 날짜 선택 전체를 차단한다. 근무시간·작업 기간 자동 산정 규칙은 새로 정하지 않는다.

## 원본·이전 흐름 보존

새 확인 문구는 `live-booking-request-ack-v2`로 저장한다. 기존 v1 서명에는 별도 제안/수락 조건이 있으므로 원본 문구·사진·가격·서명·PDF·메일·Google 이벤트를 변경하거나 새 동의로 복사하지 않는다. 기존 제출/확정 예약은 기존 읽기와 기존 확정 조건을 유지한다. 아직 서명하지 않은 요청은 새 v2 승인 snapshot으로 진행한다.

회사 예약의 확정 근거는 `customer_proposal`과 `signed_request`로 구분한다. 새 경로는 원본 v2 signed submission을 참조하며 고객의 두 번째 동의 행을 가짜로 만들지 않는다. 과거 자료를 새 경로로 일괄 변환하지 않는다.
