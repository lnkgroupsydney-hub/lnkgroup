## 구조와 검색 준비

`src/app`은 라우트·메타데이터·모듈 조립을 맡고, 정적 설명은 `service-catalog`의 content/presentation에 둔다. 공통 이미지 경로·크기·alt는 `src/shared/config/assets.ts`에서 교체한다. 정적 소개를 위해 새 DB·Repository·이벤트·미래 기능의 빈 모듈을 만들지 않는다.

페이지 고유 title·description, H1 1개, H2/H3 계층, 서버 HTML 본문, 서비스 내부 링크, 이미지 alt·크기·반응형 최적화를 준비한다. 프로토타입은 `noindex, nofollow`를 유지하며 운영 도메인·canonical·sitemap·구조화 데이터·검색 순위 보장은 추가하지 않는다. 검색 공개는 회사 정보·콘텐츠·도메인·공개 승인 이후다.

## 후속 제품 흐름 — 2026-10-02 갱신

1. Free Quote로 진입해 고객 정보·현장 디테일을 먼저 입력하고 **비공개 초안 저장**을 확인한다. 서비스 URL은 추천값일 뿐 서비스 확정이나 예약 접수가 아니다.
2. 서비스를 선택하고 같은 초안에 사진을 업로드한다. 사진 검사·소유 확인을 마친 자료만 AI 입력으로 사용한다.
3. AI가 관찰 가능한 문제점·위치·불확실성을 제시한다. 가격은 회사가 승인한 가격표로 서버에서 계산하며 AI가 금액을 만들지 않는다. 자료·가격표가 없으면 담당자 검토로 이어진다.
4. 고객이 표시된 범위·견적 버전을 **approve**한다. 이 승인은 날짜 선택으로 넘어가는 단계이고 최종 계약 서명이나 예약 확정이 아니다.
5. 앱 달력에서 시작일을 선택한다. 이미 예약된 날짜는 선택할 수 없고 서버에서도 재검사한다. 제출 후에도 회사가 기간·자원·전체 충돌을 확인할 때까지 희망일 요청으로 유지한다.
6. 최종 고객 정보·서비스·금액·약관·일정을 확인하고 전자서명한다. 견적·약관·날짜가 바뀌면 기존 서명을 사용하지 않고 다시 확인·서명한다.
7. **최종 제출**에서 서버가 현재 버전·소유권·동의·서명·가용성을 다시 확인하고 불변 제출 스냅샷과 후속 작업을 저장한다. 더블클릭·재시도는 같은 제출 결과를 반환한다.
8. 비공개 최종 견적과 서명 계약서를 생성해 고객 이메일로 발송한다. 제공자가 발송을 접수한 뒤 회사 Google Calendar 업로드 작업을 진행한다. 이메일 실제 배달·반송, Calendar 동기화·예약 확정은 각자 상태로 표시한다.
9. 마지막 작업 후 사용자의 **Complete**로 최종 인보이스를 발행하고 실제 발행일 +3 달력일을 납기로 설정한다. 제출 시 보내는 최종 견적·계약서와 인보이스는 별도다.

회사 연동 계정은 `Lnkgroupsydney@gmail.com`이다. 기존 Gmail 수집과 웹 문의 접수는 고객의 최종 서명 제출을 대신하지 않는다. 초안 저장·수신 메일만으로 회사 Calendar에 자동 확정 일정을 만들지 않는다. 담당자의 수동 검토용 비차단 일정과 고객의 최종 제출 후 자동 업로드 경로를 구분한다.

사진·서명·PDF는 비공개다. AI가 임의 금액이나 안전 판정을 만들지 않고, 동일 보수비를 중복 합산하지 않으며, 제출 스냅샷과 서명 대상 버전을 보존한다. 추가 범위·금액·날짜 변경은 새 버전과 고객 재동의를 사용한다. 예약금·자원·기간·취소 정책은 미정 상태를 유지하고 확정 전 자동 운영하지 않는다.
