# 쇼핑몰과 재고 운영

## 판매 구조

터치업 키트는 공통 고객·주문 기반을 사용한다. 고객 계정에서 주문을 볼 수 있다.

## 터치업 키트

초기 후보는 30병·50병 세트, 맞춤 회사 스티커, 지정 색상 병, 프로 키트다. 판매 전 빈 병/충전 제품, 병당 용량, 페인트 제품·베이스·광택·색상 코드, 구성 수량, 공급 가능 여부, MOQ와 납기를 확인한다. 제품 색상은 화면·카메라에서 다르게 보일 수 있으므로 사진만으로 정확한 색 일치를 보장하지 않는다.

| 유형 | 구매 흐름 | 출고 선행 조건 |
| --- | --- | --- |
| 기성 키트 | SKU 선택 → 재고 확인 → 결제 | 완제품 재고와 포장 검수 |
| 지정 색상 | 제품·색상 코드·수량 → 입력 확인 → 결제 또는 검토 | 실제 조색 가능·광택·용량 확인 |
| 로고 스티커 | 파일 제출 → 견적 → 시안 승인 → 제작 | 사용 권한 확인, 시안 버전의 명시적 승인 |
| 프로 키트 | 구성 선택 → BOM 확인 → 결제 | 전체 구성품 확보와 조립 작업 완료 |

기성 SKU와 맞춤 제작 옵션을 구별한다. 맞춤 주문은 상태가 approved_for_production이 되기 전 제작을 시작하지 않는다. 시안이 바뀌면 다시 승인받는다. 개인 변심에 대한 맞춤품 정책을 별도로 두더라도 불량·설명 불일치 등의 소비자 권리는 배제하지 않는다.

BOM은 한 키트에 필요한 병·캡·라벨·박스·페인트의 단위와 손실률을 정의한다. 구성품을 제작 투입 시 차감하고 완성품을 입고하는 모델 또는 완성품만 재고로 관리하는 모델 중 하나를 SKU별로 선택한다. 양쪽을 동시에 출고 차감해 이중 감소시키지 않는다.

도료가 포함된 경우 SDS, 누출 방지 포장, 운송사 위험물 조건을 실제 제품과 비교한다. 전 제품을 일반 택배로 보낼 수 있다고 가정하지 않는다. 승인된 배송 프로필이 없는 SKU는 공개 구매를 차단한다.

## 결제와 재고 동시성

1. 장바구니는 재고를 보장하지 않는다. Checkout 생성 시 서버에서 SKU·가격·판매 가능 지역·배송일·세금을 다시 계산한다.
2. 같은 DB 트랜잭션에서 order pending_payment와 inventory_reservation을 만들고 주문 금액을 고정한다.
3. Stripe 세션 생성은 idempotency_key로 중복 방지한다. 세션 생성 실패 시 재시도 또는 점유 해제 정책을 따른다.
4. 서명이 검증된 Webhook에서 실제 결제 성공·통화·금액·order_id를 확인한다. 성공 페이지 방문만으로 paid 처리하지 않는다.
5. 결제 성공 시 예약 수량을 확정 할당한다. 출고 시 실재고를 차감하고 예약을 해제한다. 품절·결제 경합은 한 상태 함수에서 해결한다.
6. 세션 만료·결제 실패·주문 취소는 예약을 해제한다. 늦은 결제 성공은 재고를 재확인하고 가능한 경우 확보, 불가 시 수동 처리·환불한다.

Webhook은 중복·역순·지연될 수 있다는 조건에서 설계한다. provider_event_id와 업무 의미의 중복키를 함께 확인하며, 마지막으로 도착한 메시지가 무조건 최신 상태인 것은 아니다. [Stripe Webhook](https://docs.stripe.com/webhooks)

## 세금과 배송비

GST 등록 여부와 상품별 과세 분류는 회계 담당자가 승인한다. 모든 상품을 자동 10%로 처리하지 않는다. 배송료·할인·복합 상품의 세금 배분도 확인한다. 결제·인보이스에 같은 계산 결과를 사용한다. ATO의 [GST 회계 안내](https://www.ato.gov.au/businesses-and-organisations/gst-excise-and-indirect-taxes/gst/accounting-for-gst-in-your-business)를 기준으로 검토한다.

제품 가격·배송비·불가피한 비용은 구매 결정 전에 명확히 표시한다. 주소가 있어야 계산할 수 있는 배송비는 초기부터 산정 방식과 별도 부과 사실을 알리고 최종 결제 전에 총액을 보여준다. [ACCC 가격 표시](https://www.accc.gov.au/business/pricing/price-displays)

## 반품과 정산

반품 요청 → 사유·증거 확인 → 승인 → 환불 요청 → 공급자 성공 확인 → credit note → 재고 복귀 또는 폐기 순으로 관리한다. 환불과 재고 복귀는 별개 작업이다. 부분 환불은 품목·배송·세금 배분을 남긴다. 취소 후 주문을 삭제하지 않는다.

운영자는 매일 결제 성공/DB 주문/출고 수량을 대조하고 주 1회 고회전 SKU 실사를 한다. 차이는 stock_adjustment로 담당자·사유를 기록한다. 저재고 알림은 재주문점과 공급 리드타임으로 만들고, 임의의 대량 발주 자동화는 초기 범위에서 제외한다.
