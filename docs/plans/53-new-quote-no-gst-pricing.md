# 신규 견적 A$1,450 시작가·GST 미부과

2026-10-14 로컬 구현 · 2026-10-15 회사 DB 적용·운영 배포 · Australia/Sydney

[운영 적용·기존18테이블 보존·실제 화면 검증 기록](../verification/2026-10-15-no-gst-production-release.md). 실제 신규 메일/AI/Google 제공자 전체 인수와 운영 배포를 구분한다.

## 확정한 동작

- 최초 저장하는 신규 Kitchen Cabinet Painting 요청은 가격 v3(`lk-sydney-cabinet-v3-20261014`)를 고정한다. 최소 도장비는 A$1,450, GST는 추가하지 않는다.
- 문 A$150·서랍 앞판 A$100·해당 범위의 중간 도막 보수 A$250 계산은 유지한다. A$1,450은 모든 작업의 고정 총액이 아닌 시작가다. 정확한 수량·상태·범위·최종 금액은 현장에서 확인한다.
- 고객 견적·방문일·서명·접수본, EMS 분석·예약 요약, 신규 접수/회사 예약 확정 메일과 PDF는 저장된 가격 버전으로 표시한다.
- 신규 표기는 `No GST charged. The supplier is not registered for GST.`다. 신규 금액을 `incl GST`, `ex GST`, `GST-free`, 세율 `0%`로 표시하지 않는다.

## 과거 자료 보존

요청에 가격 버전 열을 추가하되 기존 행은 NULL 상태로 남긴다. 기존 요청의 조회와 새 분석은 이전 v2 정책으로 해석하고, 새 INSERT 기본값만 v3로 설정한다. 이후 요청의 가격 버전을 바꾸는 UPDATE는 차단한다. API는 클라이언트가 보낸 가격 정책을 채택하지 않는다.

기존 분석 v1/v2, 입력 스냅샷, 승인·서명·접수·예약, 감사 기록과 이미 동결된 메일/PDF를 다시 계산하거나 덮어쓰지 않는다. 진행 중 작업은 저장된 작업 가격 버전을 사용한다. 과거 v1의 DB 완료 호환 시험과 최신 AI runner가 오래된 prompt를 실행하는 것은 별개이며, 기존 runner의 오래된 분석 계약 처리 정책도 유지한다.

이미 서명된 요청에 따른 회사 예약 확정은 원본 소계·세금·총액을 그대로 사용한다. 이전 별도 회사 제안/고객 재동의 경로의 GST 계산·표기도 보존한다. 가격 v3와 예약 acknowledgment v2는 서로 다른 버전이다.

## 구현 및 적용 순서

1. 가격 v3·이전 버전 계산/검증·요청 정책 고정을 추가한다.
2. 새 migration `20261014014608_live_quote_no_gst_pricing_v3.sql`로 버전별 DB 검증과 신규 기본값을 추가한다. 기존 migration과 기존 행은 수정하지 않는다.
3. 고객·EMS 화면과 스냅샷 기반 메일/PDF 생성 분기를 맞춘다.
4. 과거 DB 자료 해시·진행 중 분석·기존 재분석·신규 실제 SQL 예약 흐름·변조 차단을 검사한다. 과거 생성기와 PDF 바이트/메일 payload를 비교하고 신규/과거 PDF 페이지를 렌더링한다. 데스크톱·모바일에서 실제 화면을 확인한다.
5. 운영 반영은 미리 검증한 production 배포 준비 → 쓰기 잠금·보존 검사를 포함한 DB 원자 적용 → 즉시 운영 승격 순서로 실행했다. DB COMMIT 직후 약 2초에 같은 빌드를 승격했고 기존 자료는 backfill하지 않았다. 새 정책의 실제 DB 기본값과 임시 생성/롤백, 운영 가격 표시·기존 자료 해시를 확인했다. 실제 신규 고객 메일/AI/Google 전체 인수는 별도 범위로 남긴다.

로컬 실행 결과는 [로컬 검증 기록](../verification/2026-10-14-no-gst-pricing.md), 실제 운영 반영과 남은 제공자 범위는 위 운영 기록을 따른다. 이 작업에서 GST 등록 상태·사업자 이름·면허 정보·외부 계정 설정은 변경하지 않는다.
