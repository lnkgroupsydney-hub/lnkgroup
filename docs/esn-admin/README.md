## 권장 방향

**기존 Next.js 앱과 업무 DB를 재사용하고, 관리자 화면·인증·업무 모듈을 먼저 분리한다.** 회사 도메인과 배포 조건이 확인되면 `admin.<회사 도메인>`으로 관리자 진입점을 구분한다. 이 표기는 주소 형태의 제안이며 실제 DNS나 확정 URL이 아니다. 기존 지침의 단일 앱·DDD 모듈형 모놀리스를 유지하는 안이다.

이 단계는 같은 서버 런타임·배포를 공유한다. 홈페이지와 관리 시스템의 독립 배포·장애 범위까지 나눠야 한다면, 다음 단계에서 같은 저장소의 `apps/site`·`apps/admin`과 공통 업무 패키지로 분리한다. 고객 DB를 복사한 별도 시스템은 권장하지 않는다. 선택별 영향은 [분리 구조](02-separation-architecture.md)에 비교했다. **추천안은 사용자 구조 승인과 구분한다.**

## 범위

| 구분 | 계획 |
| --- | --- |
| 첫 관리자 버전 | 초대한 관리자만 로그인, 고객 검색·통합 상세, 기존 문의·데모 서명/PDF·예약·비공개 사진 조회, 출처·검토 상태 표시 |
| 운영 확장 | 관리자 처리 이력·권한 회수, 승인된 계약·가격·일정 변경, Complete·인보이스·수금, 오류 재처리 |
| 구매 관리 | 고객의 상품 주문·결제·환불·배송 이력. 기존 쇼핑몰 단계와 함께 연결 |
| 별도 확인 | 회사의 자재 매입·공급업체·발주까지 포함할지, 기존 외부 자료 이관 범위 |
| 이후 범위 | 다른 서비스·키트·식품 및 세분화한 직원 권한. 고객 계정 로그인은 ESN 관리자 로그인과 별도 |

미구현 주문/결제를 ‘0원 매출’이나 ‘주문 없음’으로 표시하지 않는다. 연결 전에는 **미연결**, 정상 조회 결과가 없으면 **기록 없음**, 실패하면 **불러오기 실패**로 구분한다. 회사 데모의 서명 자료를 운영 계약 실적으로 표시하지 않는다.
