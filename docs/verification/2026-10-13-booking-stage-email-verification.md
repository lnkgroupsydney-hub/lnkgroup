# 방문일 단계의 단일 이메일 인증 검증

2026-10-13 · Australia/Sydney · 공유 작업트리 `codex/lk-group-home-ui-ux-20261013`

[50번 계획](../plans/50-booking-stage-email-verification.md)에 따라 신규 작성의 이메일 인증을 방문일 화면에 모았다. 이전 견적 조회는 명시적인 **Open saved quote**로 분리했다. 이 후속 변경은 UI/응답 수명/회귀 검사이며 인증 제공자·서버 연결 정책·DB migration을 추가하지 않았다. 같은 작업트리의 기존 견적/입력 검증/홈/랜딩 변경을 보존했다.

## 구현 결과

- 연락처·캐비넷·사진·예상 금액에는 인증 요구를 추가하지 않는다. 방문일 카드의 저장 이메일·request ID·revision에 묶인 코드 한 번으로 현재 견적을 연결한다.
- 유효한 고객 세션·같은 이메일·현재 선택 ID·요청별 연결이 일치하면 코드를 보내지 않는다. 이미 인증된 세션의 날짜/이전 단계 왕복에도 추가 OTP가 없다.
- 현재 견적 인증 후 상세·사진 분석·현재 날짜 화면을 보존한다. 같은 이메일의 다른 견적 목록을 자동으로 열거나 선택하지 않는다. 다른 요청의 인증 응답은 오류로 처리한다.
- 다른 탭 알림과 늦은 응답은 현재 작성본을 자동 교체하지 않는다. 같은 이메일에 이미 연결된 현재 견적은 **Continue this quote**로 명시적으로 다시 선택해 입력을 유지할 수 있다.
- 관리 모드의 명시적 선택·이메일 복구와 기존 제출본의 receipt 진입을 유지한다. 실제 private request의 권한 종료는 기존 비공개 자료 정리 경계를 유지하며, 저장 전 수동 입력은 보존한다.
- 방문일에는 인증 카드 하나만 표시한다. 중복 인증 이동 버튼/안내·인증 전 날짜 안내와 Continue 동작을 숨겼으며 인증 제목·읽기 전용 이메일의 위계/간격/반응형을 정리했다.

## 수정한 회귀

정적 QA에서 관리 복원 중 request=null 전환이 응답을 취소하는 문제, 관리 인증 후 identity가 소실되는 문제, 다른 탭 충돌의 복귀 막힘과 미저장 첫 입력 소실, 숨은 접수본의 완료 화면 진입 막힘을 발견해 수정했다.

브라우저에서 관리 footer의 Back to quote를 클릭하면 React가 같은 DOM 버튼을 submit 버튼으로 재사용하면서 추가 PUT과 단계 이동을 실행하는 문제를 재현했다. 관리 닫기 버튼에 고유 key와 preventDefault를 적용하고 닫기 전후 저장 호출 수·입력·단계 보존을 확인하는 회귀를 추가했다. 첫 중간 실행의 중복 텍스트 locator strict-mode 실패는 선택자를 수정했으며 제품 동작과 구분했다.

유효 연결 세션이 방문일에 진입한 뒤 인증 메타데이터를 재확인하면, 이미 진행 중인 달력 조회가 취소됐지만 다시 시작하지 않는 read-race도 재현했다. 인증/입력 재검사 때 loaded/availability 게이트를 닫고 유효 booking state 응답으로 다시 열어 달력을 재조회한다. pending review 성공도 검증된 proof를 받은 뒤 게이트를 복구한다. 예약 body·키·날짜/시간은 바꾸지 않는다.

## 로컬 브라우저

`scripts/verify-quote-journey-ui.mjs`의 기존 11개와 새 인증 회귀 7개, 최종 **18/18 통과**. 마지막 달력/pending date·review 회귀도 좁힌 실행과 전체 실행 모두 통과했다.

- 신규 guest 견적 B의 이메일·ID·revision 바인딩 1회, 인증 응답에 이전 A가 함께 있어도 B/날짜/분석 유지와 A 자동 표시 없음.
- 유효한 현재 연결 세션은 send/verify 0회, 일반 로그인/미연결 요청은 현재 견적에 바인딩한 코드 1회.
- 다른 요청 응답 거절, 관리 목적 전환 뒤 늦은 verify 응답 무시, 다른 탭 충돌과 dirty 입력/명시적 재선택 보존.
- 저장 전 첫 입력 보존·명시적 Discard, 관리 화면 닫기에서 추가 저장 없음.
- 접근 복구 중 불명확한 예약 명령의 원래 payload/idempotency key 유지.
- 지연된 관리 read·명시 선택 복구, 제출본 receipt·다른 요청의 늦은 receipt 응답 거절.
- 기존 입력·320px/키보드·사진 분석 상태·응답 유실·409·날짜·서명·제출/새로고침 회귀.

검사는 실제 quote save/read API와 로컬 PGlite를 사용하며 고객 인증/사진/AI/예약 제공자는 합성 fixture로 대체한다. 외부 origin 요청을 차단한다. 기존 A가 선택된 세션과 미연결 guest B를 바로 연결하는 불가능한 owner 조합을 정상 흐름으로 시험하지 않는다.

최종 pageErrors(실행 예외)와 외부 요청은 0건이다. fixture가 제공하지 않는 홈 prefetch의 404와 font preload 경고는 관찰했으며 전체 console 무경고를 완료 기준으로 보고하지 않는다. 인증 전 빈 달력 wrapper의 `:visible` 검사와 정상 상태 읽기 중 즉시 enabled 검사를 화면 구조/완료 시점에 맞게 교정했다.

최신 [데스크톱 인증 카드](2026-10-13-booking-email/quote-booking-email-desktop.png)와 [모바일 코드 입력](2026-10-13-booking-email/quote-booking-email-mobile.png)을 직접 확인했다. 단일 카드·제목/이메일 위계·코드 focus·내부 스크롤·고정 footer를 확인했으며 캡처는 합성 자료다.

## 새 견적 제안과 제한

시작 화면의 **Start a new quote / Continue a saved quote** 두 진입점을 권장한다. 신규는 기존 예약·사진·서명을 보존하며 별도 요청 ID를 만들고, 복귀 선택만 견적 목록을 연다. 기존 고객의 연락처 미리 채우기는 추가 제안이다. 현재 앱의 **Open saved quote → Start a new quote → Keep saved quote and start new**는 연결 확인 후 로그아웃하고 빈 guest 작성 세션을 여는 방식으로 유지했다.

로그인 유지 상태의 새 견적 생성·미연결 요청을 기존 이메일 세션으로 즉시 연결하는 API는 이번 구현에 포함하지 않았다. 세션 만료·회수·다른 기기는 기존 재인증이 필요하다. 실제 회사 DB/인증 이메일·Google/AI/메일·실제 모바일 기기·운영 배포는 실행하지 않았다. commit·push·merge도 수행하지 않았다.
