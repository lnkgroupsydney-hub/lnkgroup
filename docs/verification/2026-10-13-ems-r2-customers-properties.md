# EMS-R2 고객·프로퍼티 구현 체크포인트

2026-10-13 · Australia/Sydney · 브랜치 `codex/ems-ux-crud-plan-20261013` · 기준 `main@756eb4d`.

사용자의 현재 변경 커밋 요청에 따른 중간 저장이다. **R2 전체 완료·운영 인수를 뜻하지 않는다.** 서브에이전트 편집은 이 체크포인트에서 중단됐고, 아래 검증과 남은 작업을 구분한다.

## 현재 코드

- 고객 중복 후보를 서버에서 조회하고 기존 고객 사용 또는 사유를 남긴 별도 고객 생성을 제공한다. 공유 이메일·전화만으로 사람을 자동 병합하지 않는다. 보관 고객도 후보에 포함한다.
- 고객 정보 수정·보관·복원, 한 고객의 여러 프로퍼티 추가·수정·보관·복원을 추가했다. 주소와 unit을 별도로 보존하고 기존 고객 `address`를 청구 주소나 현장으로 자동 이관하지 않는다.
- 고객/현장/견적 관계 저장에 revision 검사·불변 멱등 응답·감사·회사 범위 FK를 적용한다. API와 DB에서 현재 직원·세션·이메일 확인을 검사하며, 고객 Auth 접근 관계는 CRM 관계와 구분한다.
- 운영 견적의 고객/프로퍼티 연결과 Clients 통합 조회를 추가했다. `crm_revision`과 견적 콘텐츠 revision은 별도로 관리하고, 첫 연결의 실제 이메일 확인과 원본 revision을 검사한다.
- 고객 편집 UI는 409 입력 보존·최신본 확인, 결과 불명 시 고정 요청 재시도, 권한 상실 시 개인정보 제거를 구현했다. 견적 연결 UI는 원본 revision을 고정하고 변경 시 비교/재검토하며, 결과 불명 상태의 이동을 차단한다.
- 관리자 공통 CSS/UI와 R1 접근성·모션을 재사용한다. 최신 R2 fixture와 브라우저 실행기를 추가했지만 최종 브라우저 실행은 남아 있다.
- 주소의 알려진 도로명 약어·표기 차이는 정규화하고, 모호한 unit/주소의 현장 후보 검토 API·고객 관리 UI를 추가했다. 견적 연결에서 이 신규 검토 응답을 처리하는 마지막 UI 연결은 후속이다.

## 검증 상태

커밋 대상 파일을 프로젝트 지원 버전 **Node 24.14.1 / npm 11.11.0**에서 확인했다.

| 검사 | 결과 | 범위 |
| --- | --- | --- |
| 전체 `npm run test:operations` | **759/759**, 실패·취소·skip 0 | 기존 R1/업무 검사와 고객 CRM/API·입력·원본 보존 검사 |
| `npm run check` | 통과 | lint 경고 0, Next 타입 생성·TypeScript, production build |
| 별도 PostgreSQL 17.11 연결 | **10/10** | 동시 원본/연락처·현장·revision 수정/보관/복원, 불변 재시도·감사 실패 rollback·권한 차단 |
| 최종 R2 브라우저·R1 회귀 | 미실행 | 실행기/fixture 준비 상태이며 이번 커밋의 브라우저 완료로 표시하지 않음 |

중단 시점의 미연결 컴포넌트/초점 ref에서 lint 경고 2개가 발생했다. 고객 프로퍼티 검토 화면의 기존 선택·초점 복귀 연결을 마친 뒤 check를 다시 실행해 통과했다. 이 UI 동작의 브라우저 인수는 남아 있다.

최종 로그는 `/tmp/lk-ems-commit-tests.log`, `/tmp/lk-ems-commit-check.log`, `/tmp/lk-ems-commit-postgres.log`다.

- 앞선 R1 전체 739/739·check·합성 브라우저 13+1+4는 [R1 기록](2026-10-13-ems-r1-common-ui.md)의 당시 코드 검증이다.
- R2의 앞선 중간 실행은 전체 758/758·check와 별도 세션 PostgreSQL 10개 시나리오를 통과했다. 이후 주소/검토 UI 변경은 그 결과로 완료 표시하지 않는다.
- DB 검사는 회사 자료가 없는 별도 로컬 PostgreSQL 17 및 PGlite에서 실행한다. PostgreSQL 실행기는 loopback/전용 시험 사용자만 허용한다.

## 이어서 필요한 작업

1. 모호한 프로퍼티의 신규 검토 계약을 견적 연결 UI까지 연결하고 취소/기존 선택/별도 현장 확인을 검증한다.
2. 최신 R2 브라우저 실행과 R1 회귀를 완료한다. 원본 갱신 후 재검토, 결과 불명 견적 연결 재시도, 현장 후보·unit·409·401·모바일·키보드를 포함한다.
3. 수정 후 analyst 재검토와 대표 합성 화면 확인, 최종 진행표 완료 수준 갱신.
4. 실제 회사 DB 마이그레이션·배포·사용자 인수는 별도 단계다. 자동 기존 주소 backfill·고객 merge 실행·영구 삭제는 이번 코드에 포함하지 않는다.

## 저장·외부 변경 범위

새 SQL은 `supabase migration new`로 생성한 `20261013032527_ems_customer_properties_crm.sql`이다. 회사 Supabase에 적용하지 않았으며 실제 고객·메일·Google 일정·배포·원래 작업 폴더는 변경하지 않았다. 현재 요청은 이 별도 브랜치의 커밋이며 main 병합/원격 push를 포함하지 않는다.
