## 합성 화면 검증 — 실제 회사 API와 분리

기존 loopback fixture에 고객 제안 흐름을 추가했다. 페이지·정적 자산만 앱에서 읽고 모든 API·사진·PDF는 합성 응답을 반환한다. Cookie/Authorization/Set-Cookie와 업무 API를 회사 앱으로 전달하지 않는 경계를 자동 검사했다.

- 재서명 화면의 사진 두 장·원본 보존/no-AI 설명 확인.
- 동의 POST 503 후 이름·서명·동의 체크를 잠근 채 보존하고 `Retry same acknowledgement`로 복구했다. 두 요청 body와 멱등 키가 정확히 같고 서명된 상태로 전환됨을 fixture 기록과 UI에서 확인했다.
- 제안 GET 401 후 제안 상세·사진·문서·서명폼이 제거되고 만료 안내로 바뀜을 확인했다.
- GET 401 뒤 17초 동안 제안 조회 수가 5→5로 유지돼 폴링 중지를 확인했다.
- 16초 GET 응답 지연과 수동 새로고침을 함께 실행해 첫 요청 하나로 로딩이 끝나고 두 사진 제안이 표시됨을 확인했다. 15초 폴링이 정상 응답을 계속 무효화하던 경계를 재검증했다.
- 진행 중인 지연 GET과 동의 POST 403이 겹칠 때 private 화면이 제거됐고, 늦은 GET 뒤에도 만료 안내가 유지됐다.
- 제안 1 동의 POST 응답을 20초 지연하고 제안 2를 먼저 읽었다. 이후에도 제안 2·미서명 상태·동일 사진 두 장이 유지됨을 확인했다.
- 390×844 에뮬레이션에서 두 사진 카드와 긴 참조 ID가 한 열로 줄바꿈돼 표시됨을 시각 확인했다. 실제 휴대폰 터치 검증은 아니다.
- DevTools에 보인 오류는 합성 fixture의 로고 최적화 경로 404였다. 회사 앱의 동일 URL은 200이었다. 로고의 정확한 local URL·96/128/256 폭·품질 75 요청만 허용하도록 fixture를 수정하고 외부/업무 API·추가/중복 query 차단 검사를 유지했다. 관련 자동 검사·ESLint·재시작 후 세 폭 HTTP 200 확인을 완료했다. 수정 후 전체 화면 콘솔 재관찰은 Mac 잠금으로 미실행이다.

320px 전환은 도구 입력이 의도한 폭을 적용하지 못했고 재시도 시 Mac이 잠겨 완료하지 못했다. 사진 없는 v1의 실제 화면·같은 proposal/revision의 최신 전달 상태와 지연 POST 경합·최종 회사 확정도 아래 재개 항목이다. 미실행 항목을 위 자동 검사 수치에 포함하지 않는다. 확인용 스크린샷은 저장하지 않았다.

## 새 견적 전체 폼 — 후속 요청 완료

사용자가 완료 화면 대신 직접 Quote를 작성할 수 있도록 요청했다. 기존 세션을 복원하면 제출 완료 화면만 표시되고 새로 시작할 방법이 없던 흐름을 보완했다. 앞선 Mac 잠금은 이 검증 전에 해제됐다.

- 완료 화면의 Start a new quote가 새 비공개 세션을 준비하고 Open new quote form 링크가 새 탭의 빈 고객 폼을 연다. 원본 탭의 미저장 재서명·진행 중 요청은 그대로 유지한다.
- 기본 쿠키를 교체하지 않으며 URL의 UUID 선택자는 인증 수단이 아니다. 해당 HttpOnly 쿠키가 없거나 만료·변조됐으면 차단한다. 빈값/중복 선택자도 원본 세션으로 대체하지 않는다. 모든 고객 fetch·사진 src·PDF href에 선택자를 전달한다.
- 요청별 유효 세션 수 5개·발급20회/시간·입력 크기 한도를 검사한다. 재시도는 같은 nextId로 기존 유효 토큰·만료시각을 유지한다. 여러 탭의 동시 발급을 엄밀한 총5개로 제한하는 원자적 DB 계수는 추가하지 않았다.
- 전체 `npm run test:operations` **392/392** 및 격리 `npm run check`(lint·타입·production 빌드) 통과. 이후 앱 코드 변경 없이 동일 revision·같은 이메일의 미제출 named A/B PUT 상호 격리 검사를 추가했으며 해당 파일 **18/18**과 ESLint가 통과했다. 전체393개를 다시 실행한 것으로 보고하지 않는다.
