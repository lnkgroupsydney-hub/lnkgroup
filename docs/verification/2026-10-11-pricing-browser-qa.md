## 구현과 수정

- 시작가 **A$1,500 + GST = A$1,650 GST 포함**. 고객에게 세금 포함 금액을 우선 표시한다.
- 가격 버전 `lk-sydney-cabinet-v1-20261011`: 도장비는 `max(A$1,500, 문 수 × A$150 + 서랍 앞판 수 × A$100)`. 보통 수준의 도장 손상 보수는 프로젝트당 A$250을 한 번만 더한다. 일반 준비와 가벼운 보수는 포함한다. 상세 조건·근거는 [39번 가격 규칙](../plans/39-sydney-cabinet-pricing-v1.md)을 따른다. 단가는 공개 시공사 가격을 참고해 정한 초기 규칙이며 Sydney 공식 평균이 아니다.
- AI가 관찰한 수량·손상·촬영 범위를 검증한 뒤 서버와 DB가 정수 cents로 금액/GST를 계산·검증한다. 사진 부족, 수량 불일치, 추가 표면, 구조·심한·미분류 손상은 `review_required`와 총액 null로 저장한다. 시작가를 해당 요청의 총액으로 표시하지 않는다.
- 미선택 문/서랍을 비용에 포함할 수 있던 경우를 앱·SQL 모두 차단했다. 구버전 실패 분석의 명시적 재시도가 가격 버전 차이로 409가 되던 문제를 수정했고, 소유권·revision·응답 유실 재전송 검증을 추가했다.
- 브라우저 Issues에서 확인한 사진 유형 select의 name 누락을 고쳤다. 같은 컴포넌트의 파일·체크박스에도 안정적인 name을 추가했다.

## 실제 회사 Chrome · Supabase · OpenAI

회사 `lnkgroupsydney@gmail.com` Chrome에서 수행했다. 개인 창으로 전환될 때 중단했으며 사용자가 회사 창만 남겼다고 확인한 뒤 진행했다. EMS 로그인과 이메일 코드 확인은 사용자가 직접 수행했다.

1. 고객 폼에서 개인정보 없는 합성 이름/연락처·주소·서비스를 입력하고 저장했다. 요청 **RQ-D311AB1A6CEB4318AF24DFB99AC15894**, revision **4**.
2. 파일 선택창으로 사용자 지정 `damage 1.jpeg`(측면), `damage 2.jpeg`(손상)를 실제 업로드했다. 정규화된 비공개 사진 두 개의 저장/표시를 확인했다.
3. 새 `20261011005922_live_quote_pricing_v1.sql`을 회사 Supabase SQL Editor에서 실행해 `Success. No rows returned`를 확인했다. CLI migration history 등록과는 구분한다.
4. 최신 production build와 worker를 로컬 3002에서 실행했다. 고객 동의 체크 후 Tab/Return으로 실제 분석을 시작했고, 분석 중 새로고침으로 동일 작업이 복원됐다.
5. 분석 **d9e88ea5-5e4b-408d-afc2-3190e9918d82**가 **35.666초**에 성공했다. `gpt-6.1-sol / medium`, 손상 4건·제안 작업 4건, `additional_photos_required`, 가격 `review_required`/총액 null이다. 입력 1,780·출력 2,150(추론 287 포함)·합계 3,930토큰, 저장한 요율 기준 비용 추정 **US$0.02506**.
6. 완료 후 새로고침에도 같은 작업·결과·시작가·누락 범위·현장 확인 항목이 복원됐다. 실제 EMS `/admin/quotes`에서 같은 요청/사진 두 개/분석 ID/revision/가격 버전/검토 사유를 확인했다.
7. 원격 DB 읽기 및 가격 검증 함수에서 저장 결과가 유효함을 확인했다. 익명 호출은 `42501`로 차단됐다. 기존 분석 `639070a8-f858-4887-a915-711a1ffe1569`의 `awaiting_company_rates` 결과는 변경하지 않았다.
8. 회사 Chrome의 320×844 모바일 에뮬레이션에서 메뉴 열기/닫기, 결과·가격 안내·버튼의 줄바꿈을 확인했다. DevTools Console 메시지 0, Issues 페이지 오류 0/호환성 파괴 0이었다. 이미지 개선 알림은 기존 로고를 가리켰고 해당 DOM에는 이미 width/height 900이 있었다. name 수정 후에도 DevTools에 이전 연결 대상이 열리지 않는 개선 알림이 남았으므로 알림 0건이라고 보고하지 않는다. 이 알림을 실제 레이아웃 오류로 단정하지 않는다.

두 사진은 전체 캐비넷 촬영 세트가 아니다. 전체 전면/상부/하부/측면과 수량 확인이 부족하므로 실제 숫자 총액이 나온 정상 사진 세트의 인수는 아직 남아 있다. 사진을 복제하거나 합성 근거를 운영 요청에 넣어 이 조건을 우회하지 않았다. 메일·계약·Google Calendar 예약을 생성하지 않았다.
