## 구현 범위

- 서비스 상세 저장 뒤 사진 단계를 추가했다. 사진 선택·형식/용량 검사·순차 업로드·개별 실패·재시도·삭제·서버 목록 복원을 연결하며, 미완료 항목이 있으면 승인 단계 진행을 막는다.

- 새 데모 검토는 사진 목록을 포함하는 `kcp-demo-v2`를 사용한다. 기존 `kcp-demo-v1` 제출을 읽는 경로는 유지한다. 최종 고객 검토와 관리자 제출 상세에 사진 개수·참조·인증된 미리보기를 연결했다.

- 공통 서명 패드의 활성 포인터·취소·캡처 해제 등 입력 상태를 보강했다. 실제 휴대폰 검증 완료를 의미하지 않는다.

- 대상은 회사 프로젝트 `xlqyafthsxallostcqfe`다.
- `quote-photos` 버킷 생성 완료: **비공개**, JPEG 제한, 객체 최대 **6 MiB** 설정이다.
- 회사 Chrome의 Supabase SQL 화면에서 migration `20261004003752_private_quote_photos.sql`을 적용하고 `Success` 결과를 확인했다. 적용 파일 SHA-256: `eb417d7e32c7ae67dce187599248a21e0fb8c7329c4f5d3ccc3487408c6351c3`.
- 적용 후 앱 테이블 22개, RLS 활성 상태를 확인했다. 사진 테이블의 `anon` SELECT 권한과 사진 RPC의 `anon`·`authenticated` 실행 권한은 차단 상태였다. 적용 시점의 기존 제출 3건을 보존했다.
- 회사 Dashboard 보안·성능 Advisor 모두 오류 0·경고 0을 확인했다. 보안 정보 22건은 서버 전용 RLS의 정책 없음 안내다. 성능 정보 8건은 기존 예약 테이블의 FK 인덱스 7건과 `lk_outbox` 미사용 인덱스 1건으로, 이번 사진 테이블을 대상으로 한 항목은 없었다. 이 정보 항목까지 해결한 것으로 표시하지 않는다.
- 객체 저장·DB 연결 사이 응답 유실, 작업 lease와 지연 업로드 뒤 정리 경계는 격리 검사와 실제 원격 적용 결과를 구분한다. 삭제 완료 뒤 지연 PUT 객체가 생기는 경합을 재현한 뒤, 삭제 기록을 **24시간마다** 재대사하여 해당 객체를 다시 제거하도록 보강했다. 실제 회사 서비스에 장애를 주입한 시험은 아니다.

## 실제 HTTP·Storage 통합 검사

임시 `/tmp/lk-private-photo-live.mjs --supabase`의 전체 항목이 PASS했다. 스크립트는 브라우저 쿠키를 읽지 않고 새 API 전용 작성 세션 두 개를 만들었으며, 개인정보 없는 PNG fixture와 자기 시험 자료만 사용했다. 제출·메일·Calendar 명령은 호출하지 않았다.

| 확인 내용 | 실제 결과 |
| --- | --- |
| 예약·요청 재시도 | 예약 생성과 동일 본문·키의 재전송이 같은 사진 ID를 반환 |
| 업로드·동일 PUT 재시도 | PNG를 JPEG로 정규화해 비공개 저장. 같은 PUT 재전송에서 사진·내용 hash·초안 revision 유지 |

| 삭제·삭제 재시도 | 소유자의 삭제와 같은 삭제 요청 재전송 후 목록 비움, 미리보기 HTTP 404. 실제 객체 삭제와 `deleted` 기록 유지 확인 |

## 실제 관리자 API 확인

브라우저의 기존 로그인과 분리한 시험 관리자 세션으로 실제 API를 확인했다. 시험이 끝난 뒤 해당 세션을 로그아웃했다.

| 확인 내용 | 실제 결과 |
| --- | --- |
| 관리자 제출 사진 조회 | HTTP 200, `private, no-store`. 받은 이미지의 내용 hash가 제출 사진과 일치 |
| 무인증 관리자 사진 조회 | HTTP 401 |
| 다른 제출과 사진 ID를 조합한 조회 | HTTP 404 |
| 관리자 견적·약관 PDF 조회 | 두 문서의 바이트가 저장된 메일 payload의 PDF와 일치 |

관리자 **화면**은 회사 관리자 세션이 만료되어 사용자 로그인 완료를 기다리고 있다. 관리자 API 통과를 화면의 썸네일 표시 확인으로 대신하지 않는다.

## 종료 시 로컬 상태

- 최신 production 앱 `http://127.0.0.1:3002`와 반복 integration worker를 실행했다. 반복 실행에서도 새 이메일/Calendar 작업 없이 정상 조회가 이어졌다. Mac 프로세스가 실행 중인 로컬 동작이며 클라우드 상시 운영은 아니다.
- 임시 3003·3004 서버, 서명 QA 페이지, SQL 복사용 HTML, 합성 사진과 임시 HTTP 검사 스크립트는 정리했다. 회사 관리자 로그인 탭은 열어 두었으며 검증 스크린샷은 파일로 저장하지 않았다.

2. 실제 휴대폰 연결이 마련되면 M03~M05 중 손가락·여러 포인터·영역 이탈·중복 터치 등 실기기 미검증 항목을 실행한다. 반응형 화면과 controller 검사를 실기기 완료로 대체하지 않는다.
3. 사진이 포함된 회사 일정 재서명과 PDF의 시각적 서명 대조, 기타 계획의 미실행 화면·실패 경계는 후속 검증으로 남긴다. 격리 검사에서 확인한 변경·불변 조건을 실제 고객 화면에서 모두 재현했다고 보고하지 않는다.

Google 주소 검색 결제 설정은 사용자 요청 진행 중인 별도 의존성이다. 이번 예약·서명·사진 검증 기록은 결제 완료나 실제 Google 주소 자동완성 연동 완료를 의미하지 않는다.
