# L&K Group 메인 UI·UX — 구현·검증 기록

> 후속 변경: 메인 UI는 후속 브라우저 태그에 따라 그룹 배경·다섯 서비스 생성 이미지·연락처/지역/표시명을 수정했다. 현재 화면은 [최신 주석 반영 기록](2026-10-13-lk-home-revision.md)을 따른다. 아래 내용은 최초 실행 당시 기록이다.

2026-10-13 · Australia/Sydney · `codex/lk-group-home-ui-ux-20261013`.

사용자의 “계획대로 메인페이지 UI, UX 구현해줘. Coming soon 항목은 링크 없이 유지하고, 완료하면 화면 보여줘”에 따라 [48번 계획](../plans/48-lk-group-home-ui-ux-plan.md) H-01~05를 구현했다. **최종 lint·타입·빌드와 로컬 브라우저 11/11 통과.** 운영 배포·색인 활성화·커밋·푸시는 수행하지 않았다.

## 구현 결과

- 회사 소개 → 서비스 3개/상품 2개 → 회사·작업 방식 → 실제 작업 사진 → 지역 → 연락 → 푸터 순서. 기존 로컬 Manrope·Slate/Greige·Container·투명 로고를 사용한다.
- Residential Painting / Kitchen Cabinet Painting / Handyman Services / Paint Touch-up Kits / Kimchi를 한 서비스 구역에 모두 표시한다. 제품·김치를 도장 업무 견적의 ServiceId로 추가하지 않았다.
- Cabinet만 기존 상세 링크가 있다. 나머지 네 article은 `Coming soon`과 온라인 상세/주문 준비 상태를 일반 텍스트로 제공하며 링크·버튼·tabIndex·클릭/키보드 핸들러가 없다.
- Ermington 약 10km의 핵심 지역과 추가 회사 제공 지역을 구분했다. 상품·김치 배송 범위로 전환하지 않았다.
- 실제 회사 제공 표면 준비·분사 사진과 캡션, 회사 제공 도장 경력·별도 부스·담당자 Lisa·전화/메일·ABN/painting licence를 재사용한다. 새 후기·평점·가격·자격·음식 운영 조건을 만들지 않았다.
- 홈 전용 CSS module로 글자·행간·여백·상태·카드·헤더·푸터를 구현한다. 공통 토큰 값·기존 KCP/견적/EMS 화면을 일괄 변경하지 않았다.
- 홈의 고유 title·description·OG/Twitter, en-AU, 단일 H1와 H2/H3 구조를 적용한다. 모든 서비스 이름·지역 정보는 서버 HTML에 있으며 현재 noindex/nofollow를 유지한다.

## 실행 검증

검증 서버: `http://127.0.0.1:3026/`, 최종 Production build를 로컬에서 실행한다. 사용자가 화면을 볼 수 있도록 미리보기 서버를 유지한다.

추가 실제 화면 확인: 홈 title·OG/Twitter title이 모두 해당 회사/지역 제목으로 일치하며 robots는 `noindex, nofollow`다. 푸터 Back to top 클릭 후 scrollY=0·headerTop=0·focusedId=`home`을 확인했다.

테스트는 별도 Chrome 세션에서 모든 외부 요청과 실제 API 쓰기를 차단했다. 견적 진입에서 기존 화면이 자동으로 요청하는 **정확한 POST `/api/quote/requests/session`만** 브라우저 내부에서 `{ready:true}`로 응답하고 쿠키·레코드를 생성하지 않았다. 고객/견적 GET도 빈 가상 응답이다. 회사 DB·AI·메일·Calendar와 정상 저장/제출은 호출하지 않았다.

### 초기 실패와 원인 수정

첫 전체 실행은 8개 통과/3개 실패였다. 두 글자 확대 검사는 inline 값이 200%인 직후 computed 크기를 읽어 아직 16px인 상태를 검사했다. 전역 reduced-motion의 짧은 CSS 전환 때문에 프레임 뒤에 32px이 적용됐으므로 실제 크기 변경을 기다린 뒤 검사하도록 수정했다. 검사를 삭제하지 않았으며 최종 16→32px과 UI 기하를 기록한다.

나머지 실패는 견적 화면의 자동 세션 준비 POST를 의도하지 않은 업무 저장으로 분류한 테스트 가정이었다. 현행 API의 세션 준비 계약을 대조하고 위의 제한된 브라우저 가상 응답으로 수정했다. 다른 쓰기 요청은 계속 차단·실패로 기록한다. 최초 실패 화면은 증거 폴더에 보존하고 최종 결과는 11/11로 갱신했다.
