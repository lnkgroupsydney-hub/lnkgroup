최종 검증 시 공유 작업트리는 다른 채팅에서 만든 `codex/lk-group-home-ui-ux-20261013`에 있으며 기존 미커밋 변경을 보존했다. 이 입력 검증 작업에서 브랜치를 다시 전환하거나 통합하지 않았다.

[49번 계획](../plans/49-field-input-validation.md)에 따라 견적·문의·초안·고객 등록·고객/직원 인증·서명·EMS 금액/일정/설명·검색 입력에 항목별 검증을 연결했다. 파일·체크박스·선택 목록·비교 슬라이더는 기존 타입과 업무 제한을 유지한다.

## 자동 검사

- 전체 `npm run test:operations`: **746/746 통과**. 기존 733개에 공통 정책/계약/OTP 회귀 8개와 공통 UI 검증 5개를 추가했다.
- 기존 고객 인증 화면 SSR 4개는 새 공유 컴포넌트의 실제 TSX·CSS·policy를 읽도록 loader만 확장했다. 첫 전체 실행의 module resolve 실패를 수정했고 기대치를 완화하거나 검사를 비활성화하지 않았다.
- 입력 정책은 허용/거부 이메일·호주 전화·Unicode·제어문자·HTML 태그·수량 범위·우편번호를 검사한다. API 회귀는 잘못된 연락처 요청 400, 저장/OTP 제공자 호출 없음과 기존 저장본 읽기를 확인한다.
- UI 단위 검사는 숫자 원문을 변환하지 않음, 길이를 잘라 다른 값으로 바꾸지 않음, 섹션 검사의 현재 DOM 값 사용과 hidden/disabled/readonly 제외를 확인한다.
- lint·타입·production build 통과. 기존 저장본의 연락처/서비스 복합 오류 교정 보완 후 최신 build로 아래 화면 검증까지 통과했다.

## 로컬 브라우저

production build `127.0.0.1:3002`와 로컬 fixture를 사용하며 회사 DB·실제 고객 브라우저 프로필·Google·AI·메일을 호출하지 않는다. 외부 origin 요청은 차단한다.

공개 견적 `scripts/verify-quote-journey-ui.mjs` **11/11 통과**:

- 잘못된 전화·이메일·숫자만 있는 이름/주소·우편번호는 저장 요청 0건, 입력 원문·IME·필드 오류/접근성 속성과 첫 오류 focus 확인.
- 호주 번호 표기 8종 저장, 우편번호 선행 0 문자열 보존.
- 수량의 음수·501·소수·지수·전각 숫자·공백은 저장 요청 0건. 빈값/null·0·500 저장 확인.
- 설명의 제어문자·3,001자 입력 차단, 여러 줄과 Tab 저장 보존.
- 기존 6개 원페이지 회귀 유지: 응답 유실 재시도, 320px/키보드, 409/접근 종료, 분석 상태, 숨은 패널의 늦은 조회, 예상 금액→날짜→서명→제출/새로고침.
- 과거 저장본의 외국 전화번호와 HTML 서비스 설명을 읽기 overlay로 동시에 재현했다. 연락처→서비스 순서로 첫 오류를 열며 수정 전 PUT 0건, 양쪽 교정 후 현재 값으로 단일 저장을 확인했다. 변경 취소로 저장값이 복원되면 이전 오류/aria-invalid가 해소된다.

공개 검사는 실제 quote API와 로컬 PGlite를 사용하고 인증·사진 분석·메일·Google/예약 제공자는 합성 fixture로 대체했다. 별도 기존 QuoteDraftForm 화면은 코드·타입·lint·업무 회귀로 확인했으며 실제 브라우저 시나리오는 실행하지 않았다.

## 보존한 경계와 제한

쓰기 validator와 저장본 parser를 분리해 예전 견적·서명·접수증을 열 수 있다. 입력 검증은 새 시도의 payload/idempotency key를 만들기 전에 실행하며 이미 불명확한 저장의 동일 body 재시도는 유지한다. 입력 문자열·전화 포맷·Customer 이메일 대소문자·기존 optional/null 정책을 변경하지 않았다.

주소는 수동/Google 선택 입력에 같은 형식·길이 정책을 적용한다. 회사 Maps 키·결제가 아직 준비되지 않아 주소 존재 여부나 실제 Google 검색/선택은 확인하지 않았다. 이메일 존재/소유는 기존 OTP 절차가 담당하며 전화 실제 개통 여부를 조회하지 않는다. 실제 모바일 기기·회사 운영 저장/메일·Calendar·운영 배포는 이번 검증에 포함하지 않았다. 새 DB migration·commit·push·merge·운영 배포는 수행하지 않았다.
